# BH1750 light sensor

The BH1750 measures ambient light in lux. It connects to an I²C bus. Like every light sensor, it
can drive the chicken door function.

## Hardware support

The repository has a template for it on MK6, on pins `C2` / `C3`.

## Configuration

```json
{
  "peripherals": [
    {
      "name": "light-sensor",
      "type": "light-sensor:bh1750",
      "params": {
        "sda": "C2",
        "scl": "C3"
      }
    }
  ]
}
```

| Parameter | Default | Meaning |
| --- | --- | --- |
| `sda`, `scl` | (required) | I²C pins the sensor is on, e.g. `C2`, `C3` on MK6 |
| `address` | `0x23` | The sensor's I²C address (a string). The BH1750 can also be at `"0x5C"` |
| `measurementFrequency` | `60` | Seconds between readings |
| `latencyInterval` | `300` | Seconds of readings to average over |

`clkSpeed` is ignored: the driver sets its own I²C clock.

Template: [`chicken-door-mk6.json`](../../config-templates/chicken-door-mk6.json).

## Telemetry

| Feature | Unit | Value |
| --- | --- | --- |
| `light` | lx | Ambient light, averaged |

## Behavior

The sensor runs in continuous, low-resolution mode (4 lx steps). A background task reads it every
`measurementFrequency` seconds, and the reported value is the average of the last
`latencyInterval` / `measurementFrequency` readings (5 by default). A failed reading is logged and
skipped, so the average keeps its previous value. Before the first good reading the value is `0`.

Readings default to once a minute because on MK14 each one powers up the I²C port and the
valve's boost converter ([sensor power on MK14](README.md#sensor-power-on-mk14)).

If the sensor doesn't answer at startup, the peripheral fails to start.

## Limitations

- Resolution and measurement mode are fixed.
- `latencyInterval` must be at least `measurementFrequency`.
- The driver always uses the first I²C controller, bypassing the firmware's bus sharing, so it may
  clash with other I²C peripherals on the same device.
