# TI HDC2010 air sensor

The HDC2010 measures air temperature and relative humidity. It connects to an I²C bus.

## Hardware support

Any Ugly Duckling with an I²C bus can read it. The plot controller templates for MK11 use it on the
board's `SDA` / `SCL` pins at address `0x41`.

## Configuration

```json
{
  "peripherals": [
    {
      "name": "air",
      "type": "environment:hdc2010",
      "params": {
        "sda": "SDA",
        "scl": "SCL",
        "address": "0x41"
      }
    }
  ]
}
```

| Parameter | Default | Meaning |
| --- | --- | --- |
| `sda`, `scl` | (required) | I²C pins the sensor is on, e.g. `SDA`, `SCL` on MK11 |
| `address` | `0x40` | The sensor's I²C address (a string). The HDC2010 can also be at `"0x41"` |
| `clkSpeed` | `400` | I²C clock in kHz |

Templates: [`plot-controller-mk11.json`](../../config-templates/plot-controller-mk11.json),
[`plot-controller-mk11-spadefoot-toad.json`](../../config-templates/plot-controller-mk11-spadefoot-toad.json).

## Telemetry

| Feature | Unit | Value |
| --- | --- | --- |
| `temperature` | °C | Air temperature |
| `moisture` | % | Relative humidity |

If a reading fails, both values are `null`, and the reason is logged at debug level.

## Behavior

At startup the firmware puts the sensor in on-demand mode with the heater off. If the sensor
doesn't answer, the peripheral fails to start.

The sensor is read when telemetry is collected: the firmware triggers one 14-bit measurement,
waits 3 ms, and reads temperature and humidity together. Readings are reused for 1 second, so the
two features come from the same measurement. A failed reading also counts, so the sensor is tried
again after a second.

## Limitations

- The heater, interrupt output and automatic measurement modes aren't used.
